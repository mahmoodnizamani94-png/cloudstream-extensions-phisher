# StreamPlay & CloudStream SOTA Architecture Invariants (AGENTS.md)

This document defines the non-negotiable architectural invariants and priorities across `cloudstream-extensions-phisher` and the sibling host app `cloudstream`. Read and enforce these rules whenever modifying providers, extractors, rankings, playback dispatch, or download selection.

## 1. Core Quality & File-Size Priority (Non-Negotiable)
1. **720p with the Lowest File Size Possible is Priority #1**:
   - Both playback and downloads prioritize **720p HD** (`getQualityPriorityScore(720) = 10_000`) above all other resolutions.
   - Within 720p, downloads and streams **must** select the candidate with the **lowest file size possible** (derived from HTTP `Content-Length`, explicit `[XXX MB]` metadata, or HLS `#EXT-X-STREAM-INF` `AVERAGE-BANDWIDTH`/`BANDWIDTH` estimation).
2. **1080p with the Lowest File Size Possible is Priority #2**:
   - When 720p is unavailable, **1080p Full HD** (`getQualityPriorityScore(1080) = 9_000`) is the immediate next tier, strictly preferring the **lowest file size possible** first.
3. **Fallback Ladder**:
   - `720p (lowest size)` > `1080p (lowest size)` > `480p` > `360p` > `2160p`.

## 3. Anime Playback & Download Contract
- When playing or downloading Anime (both in `StreamPlay` when `isAnime == true` and in `StreamPlay-Anime` / `StreamPlayAnime.kt`), streams and downloads **must** come from the v25 SOTA Anime chain, subtitles-first:
  - **`VidLink` (100)** -> **`Cineby` (95)** -> **`CineSrc` (94)** -> **`MegaPlay` (92)** -> **`AniZone` (89)** -> **`AnimePahe` (88)** -> **`Animex` (87)**
- The host enforces an anime-only download restriction that mirrors this chain: `DownloadSelectionPolicy.ANIME_DOWNLOAD_CHAIN`, `animeDownloadPool`, `isAnimeContent`, `sortCandidates(..., anime = true)` and `orderDownloadAttempts(..., anime = true)`. When an anime pool contains no chain source the host returns no download (an explicit refusal) instead of silently downgrading to a legacy mirror. Non-anime downloads keep the universal ranking unchanged.
- Anime streams and downloads **must** preserve **original language (Japanese / Original Audio)** and **subtitles**:
  - Subtitled original-audio anime streams are badged with `[Sub] [Original]` and accompanied by `.vtt`/`.srt` `SubtitleFile` emissions so `DownloadSelectionPolicy` (`likelyOriginalLanguage` and `hasEmbeddedSubtitles`) prioritizes them above dubbed or unsubtitled streams.
  - AniZone emits the real English, non-forced, non-SDH `.srt`/`.ass` sidecars of the same episode pack; AnimePahe has no sidecars (its subtitles are part of the encode) and is kept for airing/rare-series coverage, so the independent subtitle harvester covers it. Animex is the last resort.
  - HLS master manifests containing demuxed `#EXT-X-MEDIA:TYPE=AUDIO` renditions with external `URI=` preserve the master manifest URL (using `#vid={quality}p` fragments for distinct quality routing) so ExoPlayer and `HLSDownloader` always mux the original audio track instead of downloading silent video-only segments.

## 4. Permanently Banned / Decommissioned Sources
- **VidRock (`vidrock`, `vidrock.net`, `galacticvoyagers.xyz`, `moonfirekeeper.lol`), VidSrc (`vidsrc`, `vidsrc.pm`, `cheaptruckrepairs.cc`, `netoda.tech`, `mov2day.xyz`, `vidora`), and VidSrcSU (`vidsrcsu`, `vidsrc.su`, `themoviedb.vidsrc.su`, `theemoviedb.hexa.su`, `dragonballzfans.xyz`) are permanently banned and stripped**:
  - VidRock serves non-seekable, index-less files, and the VidSrc / VidSrcSU family stalls/throttles downloads and fails reliability standards; none may ever be re-added or used for streaming or downloading. All reside permanently in `REMOVED_PROVIDER_IDS` (migration scrub), score rank `0` in `StreamLinkOptimizer.getSourcePriorityRank`, and are rejected by the host download pipeline (`StreamPlayDynamicBridge` static exclusions -> `DownloadSelectionPolicy` terminal stage `999`).
- Legacy dead/hijacked providers (`yflix`, `cinejoy`, `videasy`, `rivestream`, `videm`, `animegg`, `anichi`, `anikage`, `hianime`, `anizone`'s old extractor, etc.) remain decommissioned; their old extractor implementations, anime fan-out tasks, and dedicated tests are stripped (only `REMOVED_PROVIDER_IDS` migration entries survive). `AnimePahe` and `AniZone` were **re-admitted in v25 as new protocol implementations** after independent liveness/protocol verification (AniZone was exercised live end-to-end; AnimePahe's `.com` -> `.pw` redirect was verified and its Cloudflare gate is answered by the existing anti-bot interceptor). The old `animepahe`/`anizone` code is not used; `REMOVED_PROVIDER_IDS` no longer contains them, and both are enabled for clean installs and upgrades by the v25 migration. Any future re-admission of a listed family requires the same live evidence and fresh code, never a resurrected extractor.

## 5. Resolution Honesty Contract
- **Never synthesize a resolution.** A provider link is one piece of media; it may not be cloned into `720p`/`1080p`/`480p` companions that share the same URL. `DownloadSelectionPolicy.sanitizeLinks` in the host is the only canonical link sanitizer: it drops blank URLs, decommissioned families, download-excluded providers (when `forDownload = true`) and duplicate `providerKey|type|url` entries. It deliberately does **not** add links.
- **Extension-side inference must be honest.** `StreamLinkOptimizer.extractQualityFromText`, `StreamPlayExtractor.cinebyQualityOf` and `animexQualityOf` only accept an explicit numeric height, an exact pixel dimension, or the unambiguous acronyms `FHD`/`QHD`/`2K`/`4K`/`UHD`. Bare `HD`/`SD`/`high` are marketing grades and stay `Qualities.Unknown`. `inferQualityFromBitrate` is retired; bitrate is a display/ranking hint only and is never converted into a resolution label.
- **Size tags must be real.** A `[XXX MB]` suffix may only come from payload metadata, HTTP `Content-Length`, or HLS `AVERAGE-BANDWIDTH`/`BANDWIDTH` estimation. Fixed per-quality tables (for example the old CineSrc `720p -> 410 MB` map) are forbidden; a silent source emits no size tag and the host measures the file.
- **AnimePahe and AniZone cannot fabricate resolutions either.** AnimePahe's quality comes only from the provider's `data-resolution`/explicit `NNNp` label; AniZone's comes only from the parsed HLS master. A Kwik single-variant playlist is emitted once at its declared height (or `[Auto]` when no height is declared), never cloned into 720p/1080p companions.
- **User-facing labels must be honest.** Pickers, cast menus, download rows and subtitle dialogs display `DownloadSelectionPolicy.declaredClaimTier(link)` plus `QualityTruthRegistry` measurements. They must never display `inferredQuality`'s optimistic adaptive-stream guess. An unlabelled master shows no resolution until it has been measured.
- **Ranking may remain optimistic; presentation may not.** `inferredQuality`/`effectiveClaimTier` exist only to order candidates (an adaptive master can expose a 720p rendition). Any download attempt still verifies the delivered media before committing bytes, and fake-resolution files must be skipped in favour of an honest lower-resolution source.
- **Adaptive downloads always ask for true 720p first.** `downloadHLS` and `downloadDASH` target `TARGET_QUALITY` (720) regardless of the manifest's label, then fall back to 1080p/480p only when no 720p rendition exists. Within a tier, HLS variant selection prefers the **lowest** bitrate (`M3u8Helper2.hlsVariantComparator`) to minimize file size; DASH does the same through `DashDownloadHelper.selectBestTracks`.

## 6. English Subtitle Fallback Contract
- Provider subtitles always win. The independent fallback is used only when the provider set still lacks a downloadable English URL sidecar (`DownloadSubtitlePolicy.hasDownloadableEnglishSubtitle`) or lacks the required source diversity (`needsEnglishSubtitleHarvest`).
- `FallbackSubtitleHarvester` in the host queries five catalogues that are independent of the video mirror:
  - **Stremio OpenSubtitles v3** (`opensubtitles-v3.strem.io`) keyed by IMDb id; missing ids are resolved through **Cinemeta** (`v3-cinemeta.strem.io`) by exact/normalized title plus year and type. An unrelated Cinemeta result must resolve to `null` rather than a wrong IMDb id.
  - **OpenSubtitles legacy REST** (`rest.opensubtitles.org`) keyed by IMDb id (movie, or series with season/episode) and falling back to one title query per known title variant. Its result sets differ from the Stremio addon, so both are queried. Every `SubDownloadLink` is a gzip payload and must be inflated before format detection.
  - **Addic7ed** keyed by cleaned title, season, episode and year.
  - **YIFY Subtitles** (`yifysubtitles.ch`) keyed by IMDb id; movie-only, with zip payloads that need the page URL as `Referer` plus a browser `User-Agent`.
  - **SubtitleCat** (`www.subtitlecat.com`) keyed by release text (title plus `SXXEXX`, `NxNN` or a bare `- XX`). This is the fallback of last resort when an id-keyed index misses a release or the numbering differs, and the only fallback that answers for id-less anime. The search page links only to detail pages, so the English `.srt` link is resolved from the top candidates; a candidate is fetched only when both the title and the episode match and the release is not SDH/CC, and a page without an English file is skipped rather than guessed.
- The extension's own subtitle completion phase mirrors this coverage: `StreamPlay.kt` schedules `wyziesub`, `subtitles` (Stremio OpenSubtitles v3), `opensubtitles` (`StreamPlayExtractor.invokeOpenSubtitlesLegacy`), `addic7ed`, `subtitlecat` (`StreamPlayExtractor.invokeSubtitleCat`) and `yifysub` (movies) as dedicated non-video tasks, so a provider mirror that ships no English sidecar is filled even before the host fallback runs. `invokeOpenSubtitlesLegacy` and `invokeSubtitleCat` receive every known title variant.
- Anime must reach the same source diversity on its own surface: `StreamPlayAnime.kt` schedules `wyziesub`, `subtitles`, `opensubtitles`, `addic7ed` (verified TMDB season/episode only) and `subtitlecat` (title variants plus the verified `SXXEXX` form and the bare `- XX` form), because anime providers frequently ship no English sidecar and their episodes are indexed under English and Romaji titles. `opensubtitles` must pass the same English/Romaji/native/synonym variants as SubtitleCat. `invokeSubtitleCat` must verify title **and** episode before emitting, and must emit only the stable English `.srt` link.
- Fallback emissions carry the `X-StreamPlay-Source` provenance header (`subtitles` -> `subtitleapi` priority 105, `stremio` priority 104, `opensubtitles` priority 104, `addic7ed` priority 103, `yify` priority 103, `subtitlecat` priority 102) so `DownloadSubtitlePolicy` keeps them distinct from provider sidecars. Provider provenance markers remain 87-110 in the same registry, and `SubtitleAPI`'s marker must not claim the word `opensubtitles`.
- The catalogue inventory, liveness evidence and rejected sources (Podnapisi dead, TVsubtitles search 404, Kitsunekko Japanese-only, Subf2m expiring signed URLs, SubDL/SubSource/Jimaku/Wyzie key-gated) live in `context.md`; update it whenever a catalogue is added or removed, and keep it synchronized with the host's `context.md`.
- Fallback is best-effort and bounded: each catalogue lookup has a 6s cap, the caller wraps `harvest` in `FallbackSubtitleHarvester.TIMEOUT_MS` (15s), failures are swallowed, and a 3-minute per-title/season/episode cooldown prevents repeated network cost. Fallback must never fail playback or a completed video download.
- Fallback candidates are English-only, exclude hearing-impaired/SDH variants, are deduplicated by URL, and are saved as normal WebVTT sidecars through `DownloadSubtitlePolicy` (one sidecar per source marker, up to five English sources). The legacy REST payloads are gzip; `SubtitleBytesDecoder` inflates gzip and zip with an 8 MiB ceiling before BOM/codepage handling.
- Fallback must run on all three surfaces: playback link generation (`RepoLinkGenerator`), download-completion healing (`downloadSubtitlesForSuccessfulLink`) and offline/queued-download healing (`ensureSubtitlesForDownloadedEpisode`).
